Build dossier

Project

A transparent map of what the application does, how the Power BI connection works, what is safe to expose to the browser, and what remains external setup.

Purpose

Why this exists
A coordinated education analytics application for advisors and academic leaders. It turns the user's permitted Power BI data into three focused workflows: cohort overview, intervention triage and recognition of top performers.
Core principle
The application is a presentation and interaction layer over the signed-in user's Power BI access. It should not invent a second source of truth or bypass Power BI permissions.

How it works

1 · Identity
Microsoft sign-in establishes a stable application identity for the advisor or leader.
2 · Connection
A connect/reconnect lifecycle associates the signed-in user with their permitted Power BI access.
3 · Discovery
Workspaces and semantic models are discovered at runtime. Existing model metadata and measures are queried rather than assuming hardcoded table or measure names.
4 · Query
Power BI requests execute server-side. Dimension filter values are validated against discovered values, while viewer permissions and RLS remain effective.

Security boundary

Browser
The browser receives application-safe results and UI state. Provider tokens should never be exposed to client code.
Server
OAuth completion, Power BI requests, filter validation and connection-handle access stay server-side.
RLS
Queries execute in the context of the user's permitted Power BI access, preserving viewer-specific permissions and Row-Level Security.
